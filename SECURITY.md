# Segurança

## Versões suportadas

| Versão | Suporte a correções de segurança |
|---|---|
| 1.0.x | Sim |

Use a versão mais recente disponível dentro da linha suportada.

## Como relatar uma vulnerabilidade

Não publique detalhes de uma falha ainda não corrigida em uma issue pública. O GitHub Private vulnerability reporting está ativo neste repositório: abra a aba **Security** e selecione **Report a vulnerability** para enviar um relato privado.

Inclua, se possível, a versão afetada, o aparelho e a versão do Android, os passos para reproduzir, o impacto observado e uma forma segura de confirmar a correção. Não envie dados pessoais, mensagens, capturas com conteúdo privado ou credenciais.

## Escopo

São relevantes falhas reproduzíveis que afetem confidencialidade, integridade ou funcionamento seguro do InScreenLock, por exemplo: exposição de dados locais, autenticação contornável em condições suportadas, comportamento de overlay que comprometa a navegação segura ou uso de permissões além do documentado.

O app depende de permissões concedidas pela pessoa e das APIs do Android. Desativar Acessibilidade encerra o bloqueio; forçar a parada ou desinstalar também interrompe o controle. Essas limitações documentadas não são, por si só, vulnerabilidades. O InScreenLock não se propõe a ser resistente à adulteração do próprio dispositivo.
